# Этап «Арсенал» — дизайн-документ

Дата: 2026-07-18
Статус: утверждён пользователем (по секциям)
Предшественник: `2026-07-17-mmo-real-life-mvp-design.md` (MVP реализован и влит в main)

## 1. Обзор

Этап закрывает главную дыру MVP: деньги нечего тратить, бой скучный. Добавляем оружейный магазин, лесенку из трёх оружий, патроны как расходник и стрельбу хитсканом. Петля: зарабатывай → купи оружие и патроны → патроны сгорают, оружие сгорает при смерти/аресте → зарабатывай снова.

**Цель этапа:** деньги обретают смысл, бой и роль полиции становятся азартными. Рамки MVP-сервера (100 игроков, тик 20 Гц) сохраняются.

## 2. Решения, принятые на брейншторме

| Вопрос | Решение |
|---|---|
| Фокус этапа | Петля денег + оружие (не соцслой, не масштаб мира) |
| Тип стрельбы | Хитскан (мгновенный луч; сервер: дальность + конус + LOS) |
| Арсенал | Лесенка 3 ступени: бита → пистолет → винтовка + патроны-расходник |
| Потеря оружия | Сгорает и при смерти, и при аресте (конфискация) |
| Drive-by | Не входит; стрельба только пешком |
| Подход | Один этап целиком, один план (~10 задач), конвейер SDD |
| Инвентарь | Нет: одно оружие в руках, покупка нового заменяет старое без возврата |
| Кулаки | Остаются бесплатным базовым оружием (как в MVP) |

## 3. Данные

### 3.1 Конфиг (`shared/src/config.ts`, единый источник правды)

```ts
export const WEAPONS = {
  bat:    { name: 'Бита',     price: 150,  damage: 35, range: 2.5, cooldownMs: 800, ranged: false },
  pistol: { name: 'Пистолет', price: 600,  damage: 15, range: 40,  cooldownMs: 400, ranged: true  },
  rifle:  { name: 'Винтовка', price: 2000, damage: 12, range: 80,  cooldownMs: 120, ranged: true  },
} as const;
export type WeaponKind = keyof typeof WEAPONS; // 'bat' | 'pistol' | 'rifle'
export const AMMO_PACK_PRICE = 100;
export const AMMO_PACK_SIZE = 30;
export const AMMO_MAX = 300;
```

Кулаки: существующие константы `PUNCH_*` не меняются. Баланс правится только здесь.

### 3.2 Состояние и персистентность

- Схема `Player` += `weapon: string` (`''` = кулаки), `ammo: number` (реплицируется всем — видно, кто вооружён).
- `PlayerRecord` (SQLite) += `weapon`, `ammo`. Миграция: `ALTER TABLE players ADD COLUMN` через проверку `pragma table_info` (идемпотентно при старте `GameDB`).
- Смерть (`killPlayer`) и арест (`police.ts`) обнуляют `weapon`/`ammo`.

### 3.3 Карта

- `createCityMap` += `gunShop: Point` — оружейная лавка, квартал (2,1) у дороги. Покрывается существующими тестами «точки не внутри зданий». Клиент рисует цилиндр-метку (как у склада) — новых зданий нет.

## 4. Сервер

### 4.1 Магазин (`server/src/systems/shop.ts`)

- `tryBuyWeapon(state, playerId, kind, map): 'ok' | 'too_far' | 'no_money' | 'bad_kind'` — игрок пешком, в `DOOR_DIST` от `map.gunShop`, `cash >= price` → `cash -= price`, `weapon = kind`.
- `tryBuyAmmo(state, playerId, map): 'ok' | 'too_far' | 'no_money'` — те же проверки → `ammo = min(AMMO_MAX, ammo + AMMO_PACK_SIZE)`.
- CityRoom: сообщения `'buyWeapon' {kind}`, `'buyAmmo'`; ответ клиенту `'shopResult' {ok, reason}` для тоста. `'openShop'` клиенту по `interact` у точки (как `'openSafe'`).

### 4.2 Бой (`combat.ts`)

- `handleAttack` (сигнатура не меняется): оружие из `p.weapon`; `''` → кулаки. Ближний бой (кулаки/бита) — существующая логика с параметрами из `WEAPONS[kind]` (damage/range/cooldownMs).
- Хитскан (`ranged`): цель — ближайший игрок в пределах `range` в конусе прицела (facing-dot, порог ≈ 0.98), отрезок стрелок→цель не пересекает ни один AABB зданий. Целью может быть любой живой игрок (`mode` не `'dead'`/`'jail'`), включая водителя машины — машина укрытием не является (упрощение этапа).
- Новый хелпер в `shared/physics.ts`: `segmentHitsAABB(x1, z1, x2, z2, box): boolean` (2D, пересечение отрезка с AABB).
- Выстрел = 1 патрон: `ammo <= 0` → отказ. Cooldown из `WEAPONS[kind].cooldownMs`.
- Стрельба только `mode === 'foot'`.
- При попадании сервер рассылает всем `'shot' {from: Point, to: Point, hit: boolean}` для tracer-визуала.

### 4.3 Валидация (спека 6.2 MVP сохраняется)

Дистанция до магазина, деньги, `WeaponKind`, конус, LOS, cooldown, режим игрока — всё на сервере. Невалидное молча игнорируется (как сейчас), тик защищён существующей изоляцией ошибок.

## 5. Клиент

- **Окно магазина** — по образцу диалога сейфа (HTML/CSS поверх canvas): открывается по `'openShop'`, список оружий (имя, урон/дальность/цена) + пачка патронов, кнопки «Купить». Тост результата на `'shopResult'`.
- **HUD**: строка оружия (`Кулаки` / `Бита` / `Пистолет · 27`), подсказка у метки: «E — оружейный магазин».
- **Визуал**: tracer (тонкий светящийся отрезок `from`→`to`, ~80 мс затухания) на сообщение `'shot'`; бокс-«ствол» в руке аватара при `ranged`-оружии (читаемо, кто вооружён); красная виньетка по краю экрана при попадании по тебе (CSS, ~150 мс).
- **Звук** (опционально, выкидывается первым при урезании): один короткий щелчок через WebAudio-осциллятор на `'shot'`, без ассетов.

## 6. Тестирование

- **Юнит (Vitest):** `physics` — `segmentHitsAABB` (пересечение, касание, промах); `shop` — все ветки кодов возврата, замена оружия, `AMMO_MAX`; `combat` — дальность, конус, LOS блокирует стеной, расход патрона, отказ при `ammo = 0`, обнуление при смерти и аресте; `db` — round-trip `weapon`/`ammo`, идемпотентная миграция.
- **Интеграция:** покупка и выстрел через живую комнату (`@colyseus/testing`).
- **Гейт:** `npm test` (shared + server), `tsc --noEmit` во всех пакетах, `npm run build -w client`.
- **После этапа:** редеплой на 77.42.4.230, открытие портов, совместный ручной чек-лист (существующие 10 пунктов + оружейный блок).

## 7. Что НЕ входит в этап

Drive-by (стрельба из машины), броня/аптечки, дроп оружия на землю, инвентарь/несколько стволов, чат, уникальные ники/аккаунты, анимации персонажа, новые здания/интерьеры, NPC.
