# Пакет «прод-фидбек 1» — дизайн

> Основание: репорт с прода (mmo.expw.net): подлагивания машины, пинг не виден, на карте нет игроков, нет выхода/привязки учётки.

**Рамки:** без новых зависимостей (scrypt — node:crypto), коммиты conventional на русском, гейты после каждой задачи (`npm run typecheck`, `npm test` при серверных правках).

## T1. Пинг всегда виден
Сейчас ping шлётся только при открытой F3-панели — поэтому «не показывает». Пинг каждые 5 с постоянно (2 сообщения/5с — копейки), значение выводится в строку HUD-статов (`ui.setPing(rtt)`), F3-панель с FPS остаётся.

## T2. Игроки на карте
Миникарта и полная карта показывают других игроков точками: коп — синий, гражданин — белый, в розыске (wantedUntil публичен) — красный. Зомби пропускаем, себя пропускаем (своя стрелка есть). `MapMarker.kind` += `'player'`, цвет вычисляет main из role+wanted.

## T3. Предсказание своей машины (анти-лаг)
Своя машина сейчас рендерится по сырым серверным патчам 20 Гц — отсюда дёрганье. Перенос шага физики машины в shared: `stepCar(state:{x,z,rotY,speed}, input, dt, colliders, safeZones)` (порт из `vehicles.ts` блок водителя: газ/тормоз/драг/поворот/коллизия/разворот от беззоны). Сервер использует её же (поведение без изменений, тесты vehicles зелёные). Клиентский `Prediction` для mode='car': локальное состояние {x,z,rotY,speed}, шаг каждый кадр по текущему вводу, реконсиляция с серверным (snap при d²>9, мягкий догон 0.25..9). Своя машина и камера едут по предсказанию; чужие машины — интерполяция как раньше.

## T4. Email-привязка + выход из аккаунта
Сейчас учётка = ник + секрет в localStorage: потерял localStorage — потерял ник. Добавляем опциональную привязку email+пароль (восстановление с любого устройства). Без верификации почты (SMTP — вне рамок): email — логин, пароль — ключ.
- **БД:** колонки `email`, `passhash` (scrypt salt:hash hex); методы `bindEmail(name, email, passhash)`, `getByEmail(email) → { name, passhash } | null`.
- **onAuth(options += email?, password?):** если email дан: запись найдена → проверка scrypt, вход под её ником (токен не нужен); не найдена → привязка к нику (ник свободен или токен валиден), иначе bad_token; неверный пароль → bad_password.
- **Клиент:** экран входа — опциональные поля email+пароль (пусто = старый путь по нику); вход по email без ника (сервер вернёт name в auth, клиент берёт его из room для сохранения токена). В настройках кнопка «Выйти из аккаунта» → чистит `tok:<name>` в localStorage → reload.
- **PROTOCOL_VERSION → 5** (новые поля auth/сообщения).

## Порядок
T1 (S) → T2 (S) → T3 (M) → T4 (M+). После каждой — гейты и коммит; в конце — выкат на прод (deploy.sh) + проверка.
